좋습니다. 지금 상황은 **게스트 → 인증 사용자 전환 시스템을 안정적으로 구현하고 싶은데**,
**레플릿에서 꼬이고**, **버그도 자주 나고**, **간단하고 오류 없는 구조**를 원하시는 거죠.

그렇다면 \*\*실제로 서비스에서 많이 사용하는 '검증된 방식'\*\*으로
복잡한 상태관리를 최소화하면서 **심플하고 견고한 흐름**을 아래처럼 제안드립니다.

---

## ✅ 가장 간단하고 오류 안 나는 구조 제안

### 💡 핵심 개념:

> \*\*게스트와 인증 유저를 "한 ID 체계로 통합"\*\*하고, 인증되면 상태만 "승격"시키는 구조

---

## ✅ 추천 구조 요약

### 🟢 1. 접속 시 항상 고유 `auth_id` 생성

* UUID 방식으로 `auth_id` 생성
* `localStorage.auth_id`에 저장 (없으면 새로 생성)
* 이 ID는 **게스트든 인증자든 동일하게 사용**

```js
// 클라이언트
if (!localStorage.getItem("auth_id")) {
  localStorage.setItem("auth_id", "auth_" + generateUUID());
}
```

---

### 🔐 2. SMS 인증 완료 시, 해당 `auth_id`에 프로필 연결

* 서버에서는 `auth_id`를 기준으로 유저 DB 관리
* 인증 전: `is_verified: false`
* 인증 후: `is_verified: true`, `phone`, `ci` 등 매핑

```json
{
  "auth_id": "auth_abcd1234",
  "is_verified": true,
  "phone": "01012345678",
  "ci": "abc123cixyz"
}
```

---

### ✅ 3. API는 항상 `auth_id`로 식별

* 클라이언트가 보내는 모든 요청에는 `auth_id` 포함
* 서버에서는 `auth_id` 기준으로 설문, 로또, 포인트 등 관리

```js
fetch("/api/create-ticket", {
  method: "POST",
  body: JSON.stringify({
    auth_id: localStorage.getItem("auth_id"),
    ...
  })
})
```

---

### 🧩 4. 사용자 상태 판단 로직 (프론트)

```js
async function getUserState() {
  const auth_id = localStorage.getItem("auth_id");
  const res = await fetch(`/api/user-state?auth_id=${auth_id}`);
  const user = await res.json();

  if (user.is_verified) {
    showLoggedInUI(user);
  } else {
    showGuestUI();
  }
}
```

---

## ✅ 이 방식의 장점

| 항목             | 내용                                    |
| -------------- | ------------------------------------- |
| ❌ 상태 꼬임 없음     | guest\_id, user\_id 따로 관리할 필요 없음      |
| ✅ API 간결       | 항상 `auth_id` 하나만 사용                   |
| ✅ 인증 후 전환 간단   | `is_verified`만 true로 바뀜               |
| ✅ 로직 추적 쉬움     | 백엔드와 프론트 모두 ID 하나로 추적                 |
| ✅ 새로고침에도 문제 없음 | `localStorage.auth_id`만 유지하면 계속 사용 가능 |

## ✅ 서버 테이블 구조 예 (user\_auth)

| auth\_id      | is\_verified | phone       | ci          | created\_at |
| ------------- | ------------ | ----------- | ----------- | ----------- |
| auth\_abcd123 | false        | null        | null        | 2025-07-13  |
| auth\_def4567 | true         | 01012345678 | abc123cixyz | 2025-07-13  |

## ✅ 인증 흐름

```plaintext
[앱 진입]
↓
auth_id 생성 또는 불러오기
↓
게스트 상태로 설문/포인트 사용 가능
↓
[SMS 인증 시도]
↓
인증 성공 → DB에서 해당 auth_id → is_verified: true로 업데이트
↓
이후는 인증 사용자로 처리
```
