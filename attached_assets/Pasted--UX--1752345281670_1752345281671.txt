지금 설명하신 구조를 보면 **게스트 모드와 인증 유저 모드가 동시에 존재**하는 **하이브리드 사용자 시스템**입니다.
이런 구조는 실제로도 **UX는 좋은 반면, 버그가 생기기 쉬운 3가지 핵심 이유**가 존재합니다.

---

## ✅ ⚠️ 자주 발생하는 문제 원인

### 1. **guest\_id → user\_id 전환 시 상태 동기화 실패**

* `localStorage`에 guest\_id가 남아 있는데 서버는 이미 user\_id로 전환
* 인증 완료 후에도 앱/웹이 이전 상태(게스트)로 동작함
* 특히 **리프레시나 인증 후 리다이렉트 시** 버그 자주 발생

✅ **해결책**:

* 인증 완료 시 **guest\_id 제거 후 user\_id로 갱신**

```js
localStorage.removeItem("guest_id");
localStorage.setItem("user_id", response.user_id);
```

* 이후 API 호출 시 항상 user\_id가 우선되도록

---

### 2. **중간 인증 상태 (전화번호 인증 중)에 접근한 사용자 처리 미흡**

* 인증코드 입력 중에 다른 페이지로 이동 → 다시 돌아오면 상태 꼬임
* 또는 인증 도중 뒤로가기/새로고침 시 `codes`가 날아감

✅ **해결책**:

* 인증 중인 상태를 localStorage에 `auth_pending: true`로 저장
* 인증 완료되면 `auth_pending: false + user_id 저장`
* 인증 도중 이동하면 자동으로 인증창으로 리다이렉트

---

### 3. **API가 guest\_id와 user\_id를 동시에 처리하는 구조 혼란**

* 어떤 API는 guest\_id 기준으로 동작, 어떤 건 user\_id 기준으로 동작
* 예: `/create-ticket` → guest\_id로 생성됐는데 이후 `/my-tickets`는 user\_id로 조회 → 에러 or 빈 결과

✅ **해결책**:

* 모든 API 요청 시 **user\_id 또는 guest\_id 명시**
* 서버에서 내부적으로 `authUserId = user_id || guest_id` 로 처리

```js
const authId = req.body.user_id || req.body.guest_id;
```

---

## ✅ 올바른 구조 요약

| 사용자 상태 | localStorage / 서버 처리             | API 호출 시             |
| ------ | -------------------------------- | -------------------- |
| 게스트    | `guest_id`만 존재                   | 모든 요청에 `guest_id` 포함 |
| 인증 중   | `guest_id` + `auth_pending=true` | 인증 완료 후 전환           |
| 인증 완료  | `user_id` 저장, `guest_id` 제거      | 모든 요청에 `user_id` 사용  |

---

## ✅ 프론트 기준 체크리스트

* [ ] 처음 진입 시 guest\_id 자동 생성 및 저장
* [ ] 인증 시도 시 `guest_id` → `user_id` 전환 로직 정확히 동작
* [ ] 인증 완료 후 페이지 리프레시 or redirect 에도 상태 일관성 유지
* [ ] 인증 후 요청은 모두 `user_id` 기준으로 전환
* [ ] 중간 상태(인증 중)에 유저가 이탈해도 이상 동작하지 않도록 보호

---

## ✅ 서버 기준 체크리스트

* [ ] 모든 API는 `user_id` or `guest_id`를 동시에 인식 가능하게
* [ ] 인증 완료 시 `guest_id`로 생성된 기록들을 `user_id`에 병합 (선택)
* [ ] 인증번호 저장은 반드시 TTL 있는 저장소 (예: Redis)

---

## ✅ 제안: 간단한 구조 리팩터 예

```js
// getAuthId(): 항상 유저 인증 상태 파악
function getAuthId() {
  return localStorage.getItem("user_id") || localStorage.getItem("guest_id");
}

// 서버에서 모든 요청에 적용
const authId = req.body.user_id || req.body.guest_id;
```

---

## ✅ 마무리 제안

1. 구조가 꼬이기 시작했으면 **guest와 user 상태를 완전 분리**하는 구조로 정리 필요
2. 인증 전후 상태를 `localStorage`, `session`, `서버 DB`에서 **일관되게 동기화**하는 것이 핵심
3. 가능하면 인증 완료 시 백엔드에서 guest\_id 기록을 `user_id`에 이관해주는 것도 매우 유효

---

필요하시면:

* ✅ 상태관리 플로우차트 (guest → user)
* ✅ 통합 API 핸들링 구조
* ✅ 오류 자동 복구 로직

도 바로 도와드릴게요. 혹시 코드 공유해주시면 정확히 디버깅도 도와드릴 수 있습니다.
